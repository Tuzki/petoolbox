# PE Toolbox SEO Contract

## Purpose

This document records the SEO behavior that is implemented on the current `develop` baseline and must not be changed accidentally. It is a contract for public URLs, localized metadata, indexing controls, redirects, and discovery files. It does not introduce a new routing or SEO system.

The canonical production origin is:

`https://www.petoolbox.tech`

Vercel Preview URLs, branch deployment URLs, localhost, `petoolbox.vercel.app` hosts, and the non-`www` domain are not canonical production origins. They must not appear in production canonical links, hreflang links, robots sitemap declarations, or sitemap entries.

## Current implementation

### Production origin and site mode

Both `astro.config.mjs` and `src/lib/site.ts` use `https://www.petoolbox.tech` as the default site URL. `src/lib/site.ts` exposes that value through `site.url`, and `canonicalUrl()` joins it with an absolute path.

`PUBLIC_SITE_URL` can override the default at build time. Any production build or deployment configuration that sets this variable must still resolve to `https://www.petoolbox.tech`. A preview or local value must never be used to generate production SEO output.

The site also supports a guarded private mode in `src/lib/site.ts`. Private mode is enabled only when `PUBLIC_SITE_MODE` is `private` and `PUBLIC_ENABLE_PRIVATE_MODE` is `true`. In private mode, `BaseLayout.astro` emits `noindex, nofollow`, and the robots endpoint disallows crawling. Public production output must use public mode.

### Localized public routes

Public indexable pages use explicit language prefixes:

- English: `/en/`
- Simplified Chinese: `/zh/`

`astro.config.mjs` declares `en` and `zh`, uses English as the default locale, and sets `prefixDefaultLocale: true`. Therefore English is not exposed as an unprefixed indexable default page.

Formal page files under `src/pages/en/` and `src/pages/zh/` provide symmetric localized routes. Tool routes currently delegate to a shared page implementation with an explicit `locale="en"` or `locale="zh"`. `src/lib/i18n/routes.ts` generates localized paths with a trailing slash.

`vercel.json` redirects only the root path `/` to `/en/` with a non-permanent Vercel redirect. Do not infer other redirect behavior from that one rule.

### Canonical and hreflang

`src/layouts/BaseLayout.astro` owns metadata for normal localized pages. It:

- converts the page path to the current locale with `getLocalizedPath()`;
- emits a canonical URL using `canonicalUrl()`;
- derives a locale-neutral path with `stripLocalePrefix()`;
- emits an English alternate with `hreflang="en"`;
- emits a Chinese alternate with `hreflang="zh-CN"`;
- emits `hreflang="x-default"` pointing to the English formal URL;
- uses the same canonical URL for `og:url`.

Every localized page must therefore have a self-referencing canonical on `https://www.petoolbox.tech`. The English and Chinese pages for the same content must reference each other with matching hreflang links. The x-default link must point to the English version.

Do not pass a pathname to `BaseLayout.astro` that maps one locale to another slug or produces a canonical different from the page's formal localized URL.

### Legacy unprefixed routes

Existing unprefixed routes under directories such as `src/pages/tools/`, `src/pages/articles/`, `src/pages/about/`, and the other unprefixed category directories are compatibility routes, not a second set of indexable pages.

The current compatibility mechanism is `src/components/LegacyRedirect.astro`. A legacy page using it:

- targets the corresponding English formal route;
- emits `noindex, follow`;
- emits an immediate meta refresh;
- calls `location.replace()` in the browser;
- sets its canonical to the English target;
- provides a normal target link as a fallback.

Preserve the repository's existing compatibility approach unless a route migration task explicitly defines a replacement. An unprefixed legacy path must not render a full indexable duplicate of an English or Chinese page.

The root `/` is handled separately by the Vercel redirect in `vercel.json`. Do not add or change Vercel redirects as incidental SEO cleanup.

### Robots behavior

There is no `public/robots.txt` on the current `develop` baseline. Robots output is generated by `src/pages/robots.txt.ts`.

In public mode it emits:

- `User-agent: *`;
- `Allow: /`;
- a sitemap URL on `https://www.petoolbox.tech` through `site.url`;
- a Host line using `site.url`.

In private mode it emits `Disallow: /` instead. Do not add a second static robots file or unintentionally change these public/private semantics. Production robots output must not advertise a preview, branch, localhost, Vercel, or non-`www` sitemap URL.

### Sitemap behavior

The sitemap endpoint is implemented by `src/pages/sitemap-index.xml.ts`. Despite its filename, the current response is one XML `<urlset>` rather than a sitemap-index document containing child sitemaps.

The implementation:

- includes a fixed set of public static routes for both locales;
- includes each tool in `src/data/tools.registry.ts` only when its status is `available` and it has a route;
- includes localized published articles returned by the article loader;
- generates both `/en/` and `/zh/` URLs through `getLocalizedPath()`;
- creates absolute URLs from `site.url`;
- removes duplicates with a `Set` and sorts the final paths.

Do not describe or treat `coming-soon` registry entries as published sitemap URLs. Do not add legacy unprefixed compatibility routes to the sitemap. Sitemap entries must use the production `www` origin and formal localized routes only.

## Stable URL contract

A published slug that has been deployed and submitted for indexing must not be renamed, removed, or assigned a different canonical without an explicit migration plan. A migration plan must account for, as applicable:

- the old URL and its redirect or compatibility behavior;
- the new English and Chinese formal URLs;
- canonical and reciprocal hreflang changes;
- internal links and navigation;
- sitemap removal and addition;
- legacy unprefixed routes;
- tests and post-deployment verification.

Deleting a route file or changing a registry slug is not a complete migration. Never create two indexable URLs with the same localized content and competing canonicals.

## Contract for a new public tool

Before a tool is treated as publicly available, it must have:

- an English formal route under `/en/`;
- a Chinese formal route under `/zh/`;
- the same functionality and route shape in both locales;
- one unique, clear H1 on each localized page;
- a localized title and meta description for English and Chinese;
- a self-referencing canonical on the production `www` origin;
- reciprocal English and Chinese hreflang links;
- x-default pointing to the English formal route;
- localized internal links that keep users within the active locale;
- an appropriate legacy compatibility route when the existing route pattern requires one;
- an `available` registry entry with a route so the current sitemap implementation includes both localized URLs;
- explicit tests for route generation, metadata, localization, links, and browser behavior when those surfaces change.

Do not publish one locale before the other. Do not expose a coming-soon registry entry in the sitemap merely because its title and description already exist in locale files.

## SEO-sensitive files

Treat changes to these current files and areas as SEO-sensitive:

- `astro.config.mjs` — site origin, locale list, default locale, and prefix routing;
- `vercel.json` — the root HTTP redirect;
- `src/lib/site.ts` — site origin, public/private mode, and canonical URL construction;
- `src/layouts/BaseLayout.astro` — title, description, robots meta, canonical, hreflang, x-default, and Open Graph URLs;
- `src/lib/i18n/config.ts` — locale identifiers and HTML/Open Graph locale values;
- `src/lib/i18n/routes.ts` — localized path generation, locale swapping, and trailing-slash behavior;
- `src/pages/en/` and `src/pages/zh/` — formal localized routes;
- unprefixed compatibility routes under `src/pages/` and `src/components/LegacyRedirect.astro`;
- `src/pages/robots.txt.ts` — generated robots behavior; there is currently no `public/robots.txt`;
- `src/pages/sitemap-index.xml.ts` — sitemap route selection and output;
- `src/data/tools.registry.ts` — tool publication status and route data used by the sitemap;
- `src/locales/en/` and `src/locales/zh/` — localized titles, descriptions, navigation labels, and page copy;
- `src/components/Header.astro`, `src/components/Footer.astro`, and registry-backed navigation data — localized internal links and language switching;
- article content and article-loading code when publication state, slug pairing, or localized availability changes;
- `tests/site-build.test.mjs` and `tests/browser-smoke.mjs` — current assertions for formal routes, metadata, SEO alternates, legacy behavior, localized links, robots, sitemap, and canonical output.

This list identifies the current implementation. It does not authorize changes to these files without task scope.

## Required SEO validation

Any change involving routes, layouts, metadata, canonical URLs, hreflang, robots, sitemap generation, redirects, publication status, internal links, or localization requires explicit SEO validation. A successful TypeScript or Astro check alone is insufficient.

At minimum, validation must confirm:

- English and Chinese formal routes are both generated;
- every affected page has exactly one clear H1;
- titles and descriptions are present and correctly localized;
- each canonical is self-referencing and uses `https://www.petoolbox.tech`;
- English and Chinese hreflang links are reciprocal and use the correct formal URLs;
- x-default points to English;
- no preview, branch, localhost, Vercel, or non-`www` origin appears in SEO output;
- legacy unprefixed pages remain non-indexable compatibility pages and point to the intended formal URL;
- localized internal links stay in the active locale and language switching preserves the equivalent route;
- public robots output allows crawling and advertises the production sitemap;
- private-mode robots and meta behavior remain intentionally restrictive when private mode is explicitly tested;
- the sitemap contains intended published English and Chinese URLs only;
- unavailable, draft, retired, legacy, preview, and duplicate URLs are excluded;
- trailing-slash behavior remains consistent with `getLocalizedPath()`;
- generated output and browser behavior agree.

Use the repository's normal validation sequence, including `npm run check`, `npm run build`, and `npm run test`. Run `npm run test:browser` for changes affecting pages, routes, navigation, metadata visible in the browser, language switching, redirects, or responsive/browser behavior. The browser suite requires a running preview URL as configured by the existing test script.

## Pre-release checklist

Before releasing an SEO-sensitive change:

1. Review the complete Git diff and confirm every SEO-sensitive modification is in scope.
2. Confirm the production origin remains `https://www.petoolbox.tech` in generated output.
3. Build the site and inspect the affected English and Chinese HTML files.
4. Verify H1, localized title, localized description, self-canonical, reciprocal hreflang, and English x-default.
5. Verify the equivalent formal routes and localized internal links.
6. Inspect affected legacy output for `noindex, follow`, the English target, and target canonical.
7. Inspect generated `robots.txt` and `sitemap-index.xml` directly.
8. Confirm the sitemap contains the intended formal localized URLs and no duplicate or non-production origins.
9. Run the site-build tests after a current build so tests read current `dist/` output.
10. Run browser validation when the change affects browser-visible SEO or route behavior.
11. Check the deployed production output after release when URLs, redirects, indexing controls, or discovery files changed.

Do not rename or remove an indexed URL, alter canonical ownership, or change redirect behavior until the migration plan and verification steps are explicit.
